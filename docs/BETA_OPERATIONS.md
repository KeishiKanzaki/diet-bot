# 0円で進める少人数βの運用

2026-10-20作成。利用者への連絡、募集、広告、外部サービス契約はまだ行っていない。
運営者・問い合わせ先・正式ポリシーは利用者の指定により保留中。
それらが決まるまでは、運営者本人の動作確認と募集文面の準備まで進める。

## 今回の実機確認（AI呼び出し不要）

先に「今日」で元の件数・合計を控える。番号は実際に返された値を使う。

| 順番 | LINEで送る文章 | 確認すること |
|---|---|---|
| 1 | 記録 動作確認用 600 | 1件増え、番号と「入力値」が返る |
| 2 | 今日 | 元の件数+1、合計+600kcal |
| 3 | 履歴 | 動作確認用の記録と番号が表示される |
| 4 | 訂正 番号 動作確認用 550 | 同じ番号が550kcalに変わり、PFCは不明になる |
| 5 | 今日 | 元の件数+1、合計+550kcal |
| 6 | 取消 番号 | 確認文が返る。この時点ではまだ残る |
| 7 | 今日 | 前の集計と同じで、まだ1件分が含まれる |
| 8 | 取消確定 番号 | そのテスト記録だけ消える |
| 9 | 今日 / 履歴 / 7日間 | 元の件数・合計に戻り、テスト記録が残っていない |

テスト中に別の食事を記録した場合は、その分を考慮する。
本物の食事記録を使って取消試験をしない。取消済みの記録は元に戻せない。
すべて上記の固定コマンドで確認し、会話や写真解析の試験はここでは行わない。

## 初回体験

正式ポリシー等を準備した後、まず知人など最大5人を対象に3日間試す案。
招待や個別連絡は実施していない。連絡先・病歴・体重などを追加収集しない。
AIを使わず開始する場合も「プライバシー」→「同意する」から始める。

利用者が送る例:

```text
記録 おにぎり 180
今日
履歴
7日間
```

入力値は利用者が把握している食品表示などに基づく。アプリがその精度を保証するものではない。
カロリーを把握できない場合は、推測値を無理に入力させない。
写真解析はGoogleの無料枠確認と同意の説明が済んだ状態でだけ使用する。

## 毎日の運用

- Googleは無料枠のまま、有料枠や別モデルへ自動切替しない。
- `/cost-status`と`/version`を確認する。診断自体はAIを呼ばない。
- 各管理画面で無料枠の使用量と請求設定を確認する。
- AI枠が足りなくなったらAIを停止し、手入力を案内する。有料プランへ変更しない。
- DBやホスティングの無料枠に近づいた場合は新規招待を止め、使用量を確認する。
- 障害報告には操作名と時刻だけを残し、秘密キーや食事原文をログへ追加しない。

正式ポリシーの公開と連絡先確定は、一般公開や招待募集の前に残っている作業。
