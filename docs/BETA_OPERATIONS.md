# 写真中心の少人数β運用

2026-10-20更新。[承認済み方針](LAUNCH_PLAN.md)に合わせ、手入力や週報の操作試験を主目的にしない。
運営者名・問い合わせ先・公開ポリシーが未確定なので、募集・招待・個別連絡は保留。

## 最初の確認

ローカルの自動テストは通信をモックし、AI APIへ実リクエストを送らない。
本番反映後は運営者がLINEで「使い方」を確認。同意済みなら食事写真を1枚送り、
料理名・推定カロリー・食事に合う工夫1つ・励ましが短く返ることを確認する。
写真の実送信は現在の無料枠を消費する。開発エージェントは勝手に実API試験を実施しない。
使い方や写真返信にPFCやコマンド一覧が出ないことも確認する。

## 5人・7日間の検証案

公開文面と招待準備が整ってから、写真を送る体験だけを試してもらう。
操作は「プライバシー」→「同意する」→食事写真。毎食の記録を強制しない。
画像・会話本文・LINE IDを評価表へ転載せず、P1〜P5の匿名記号で必要最小限を記録する。

| 確認すること | 見方 |
| --- | --- |
| 最初の写真を送れたか | 詰まった操作と成功人数 |
| また使ったか | 7日間の利用日数と再利用の理由 |
| 工夫が食事に合っていたか | 本人の評価と、合わなかった例の要約 |
| 励ましが心地よかったか | 責められた感じや定型文の違和感を聞く |
| 月額480円でも続けたいか | 仮説として聞く。契約や決済は開始しない |

少人数の結果を市場全体の需要と見なさない。新機能の要望より、写真を送らなくなった理由を優先する。
無料枠・障害・応答の問題があれば利用人数や回数を制限し、必要なら停止する。
費用を伴う設定変更や有料への自動切替はしない。

## 返信のレビュー

[返信ガイド](YUKI_REPLY_GUIDE.md)で調子と長さを合わせる。
モック試験は実モデルの助言品質や写真推定精度を証明しない。実返信は人が確認する。
記録の誤りや望まない返信を無視せず、まず核となる返信を改善する。
