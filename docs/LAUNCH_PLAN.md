# 開発・実用化・収益化計画

作成日: 2026-10-18。以下の価格と目標は検証する仮説であり、市場相場や実績ではない。

2026-10-19更新: 利用者が初期費用・運用費0円を指定。
以下の課金・広告・有料インフラを使う案は、自動実行の対象から外す。
費用発生には金額と条件を示したうえで別途明示承認が必要。
現時点では[ゼロコスト確認](ZERO_COST_AUDIT.md)を先に完了し、無料枠超過時は制限・停止する。
料金・決済の記載は将来の検討資料であり、支払い設定や有料APIの有効化を許可するものではない。

## 現状の判断

既存アプリの価値は「アプリを開かずLINEに食事を送れる」こと。
初期顧客は18歳以上の一般成人で、詳細な入力が続かず食生活を振り返りたい人。
最初の価値は体重減少そのものより、記録の継続と振り返りに置く。

当初は1ファイルの試作で、旧Google SDK依存、Supabaseが依存一覧に未記載、同意・削除・上限がなかった。
今回、無料の招待制β版として基本機能を整備した。既存の写真→PFC→今日の合計という返信構成は継承。

## 6週間の実行順序

| 期間 | やること | 終了条件 |
|---|---|---|
| 第1週 | 実DB照合、デプロイ、運営者情報とポリシー、実LINEで受入テスト | READMEの全受入項目に証跡 |
| 第2週 | 10人を手動招待、初回体験を観察、食事写真30例を人が確認 | 初回記録成功80%以上、重大な不適切応答0件 |
| 第3週 | 記録訂正・取消、7日間サマリー、非同期処理と削除競合対策 | 訂正と再試行で二重計上しない |
| 第4週 | 30人まで拡大、離脱理由を確認、原価を計測 | 7日後に再利用40%以上、週3日記録30%以上 |
| 第5週 | 費用をかけずに有料意向と提供価値を検証 | 自動契約や決済開始をせず需要を確認 |
| 第6週 | 0円で続けられる範囲を判断し、収益化の費用条件を提示 | 費用を伴う施策は明示承認まで保留 |

目標未達なら広告や機能の大量追加を止め、離脱原因を改善する。
利用者への連絡・広告出稿・アカウント開設・本番課金はまだ実施していない。

## 商品と料金の仮説

- 無料β: 現実装。1日10回までの画像・相談の合計。失敗もカウント。
- 有料β案: 月額980円、写真月90件＋7日サマリー＋記録訂正。まだ未実装。
- 将来案: 管理栄養士本人のレビューを別料金で提供。資格者との契約・稼働・責任範囲が整うまで販売しない。

「AI管理栄養士」と断定する表現は使わず「食生活を支えるAI」として案内する。
正式な監修者がいない状態で「管理栄養士監修」と表示しない。
体重減少や栄養値の正確性を保証しない。個別治療や疾患別の食事療法を販売しない。

## 原価と損益の確認

売上だけでなく、Google API・LINE・ホスティング・DB・決済・返金・サポート時間を集計する。
実際の価格は各契約・モデル・プランを確認する。ここでは未確認のAPI単価を固定しない。

仮に月980円、変動費上限294円/人なら限界利益686円/人（70%）。
固定費10,000円/月なら約15人でインフラ固定費相当を回収するが、人件費・税・獲得費は含まない。
90件/人でAPI予算を180円に置く場合、1件あたり2円以下が必要。
この数字は予算からの逆算であり、実コストの推定ではない。
上記は当初案の比較用仮説であり、現在の0円運用で支出してよい予算ではない。

実測: 各モデルの入出力トークンとGoogle請求、LINE送信数、障害率を日次集計。
画像サイズ・会話長を固定し、10人×7日分から中央値と高利用者の費用を確認する。
予算超過なら無料上限・有料枠・モデル選定を調整。課金後の条件変更は明示して通知する。

## 課金実装の仕様（次段階、未実装）

1. LINE Login / LIFFによる本人確認。ブラウザから届いたuser_idをそのまま信頼しない。
2. サーバー側で認証済み利用者とStripe Customerを紐づけ、固定のPrice IDでCheckout Sessionを生成。
3. 生のリクエスト本文とStripe署名を検証。イベントIDをDBで一意に保存。
4. 成功画面への遷移では権限を付与せず、支払・契約状態の確認結果で利用枠を更新。
5. 支払失敗、解約、期間末解約、払い戻し、順不同イベントを扱い、Stripeとの定期照合を行う。
6. Customer Portalで支払方法と解約を提供。アプリ内データ削除と購読解約の関係を明確にする。
7. 特商法表示、税込価格、更新周期、解約方法、返金条件、利用規約を公開してから本番決済。

既存アプリには認証済みWebセッションがないため、決済URLへのLINE IDの直付けは採用しない。

## リリース前に運営側が確定すること

- LINE公式アカウント、Google AI、Supabase、ホスティングの所有者と請求設定
- 運営者の名称・問い合わせ先・公開ドメイン・対象地域
- 実データの保存期間、委託先・国外取扱い・削除とバックアップの説明
- 管理栄養士監修の有無、利用規約とプライバシー文面の確認
- Googleのデータ利用条件を利用予定の契約で確認。無料枠と有料枠の取扱いを同一と仮定しない
- DBの実環境試験、負荷試験、障害通知、予算上限、バックアップ復旧

AIのプロンプト制約だけで安全を保証できない。βでも危険な応答が出たら対象機能を停止し、
レビューと改善を行う。原文ログを無制限に集めることはせず、評価用データは同意と匿名化を前提にする。
